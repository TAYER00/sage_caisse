# OBJECTIF DU PROJET

Développer une application web externe permettant aux employés de saisir et suivre facilement les opérations de caisse et de dépenses, en s’appuyant sur les données initiales de Sage 100.

L’application doit gérer :
- Les alimentations de caisse
- Les dépenses de caisse
- Les remboursements
- Les bénéficiaires des opérations
- Les responsables des opérations
- Les justificatifs
- Les validations
- La traçabilité complète des mouvements
- L’impact des opérations sur le solde de chaque caisse

Exemple fonctionnel :
Un employé demande une avance pour un déplacement professionnel.

Il crée une opération avec :
- La caisse concernée
- Le type d’opération : alimentation, dépense ou remboursement
- Le motif : frais de déplacement
- Le bénéficiaire : employé concerné
- Le responsable de l’opération
- La date de l’opération
- Le montant
- La société
- Le compte financier
- La répartition analytique
- Le justificatif : facture, reçu, PDF ou image
- Une observation libre

L’opération commence en brouillon.

Après vérification, un responsable autorisé valide l’opération.

L’opération validée peut ensuite être comptabilisée selon les règles de gestion définies.

Chaque changement doit être historisé.

# STATUTS DE L’OPÉRATION

L’application doit gérer les statuts suivants :

1. Brouillon
- Création de l’opération
- Modification des champs
- Ajout ou suppression de justificatifs
- Possibilité d’annuler ou supprimer selon les règles de sécurité

2. Validé
- Validation obligatoire par un utilisateur autorisé
- Enregistrement de l’identité du validateur
- Enregistrement de la date et de l’heure de validation
- Blocage des modifications sensibles
- Conservation de la traçabilité

3. Comptabilisé
- Enregistrement de la comptabilisation
- Traçabilité de l’utilisateur responsable
- Date de comptabilisation
- Référence comptable Sage si disponible
- Vérification de l’impact financier

4. Annulé
- Conservation de l’historique

IMPORTANT :
Ne jamais confondre validation interne et comptabilisation réelle dans Sage 100.

L’application doit d’abord fonctionner sans écrire dans les tables comptables de Sage.

La comptabilisation réelle sera étudiée séparément avec les mécanismes officiellement supportés par Sage.

1. Mode autonome :
- L’application enregistre les opérations dans sa propre base

- Sage est consulté en lecture seule

- Après validation, les opérations sont réellement enregistrées dans Sage
- Uniquement via un mécanisme officiellement supporté

Recommandation :
